# DsCppModManager — 버전 기록 (정본)

버전 규칙은 저장소 루트 `VERSIONING.md` 를 따른다.
각 판의 실측·사고·설계 근거 전문은 `STATUS.md` 의 해당 절에 있다 — 여기는 **무엇이
바뀌었는지**만 적는다. (최신이 위)

---

## v0.51 — 2026-08-21

**config.ini 실수(소수) 값도 조절 가능 (사용자 피드백)**
- `0.5`, `1.0`, `0.25` 같은 소수 값에도 조절 버튼(◀▶)이 생긴다. 정수는 되는데
  실수는 안 되던 것의 보완.
- **조절 단위(0.1 / 0.01)를 고를 수 있다** — `◀` 왼쪽의 **"조절 단위" 콤보박스**
  (`±0.1` ▼)로 선택한다. 패드는 그 행에서 A 버튼.
- 저장은 원본 표기 그대로 — `1.50` 으로 적혀 있던 값은 `1.50` 형식을 유지한다.
- 소수 3자리 이상·지수 표기 등은 종전처럼 표시만 한다(안전).

## v0.50 — 2026-08-13

**config.ini 브리지 (넥서스 모드 호환)**
- 옵션을 하나도 선언하지 않은 모드라도 폴더에 `config.ini` 가 있으면, 그 값들을
  이 패널에서 바로 켜고/끄고/숫자 조절할 수 있다. (예: 대화 초상화 오버레이 모드)
  - 섹션(`[Overlay]` 등)은 제목 행으로, 그 아래 키가 자식 항목으로 들여써져 나온다.
  - `0/1` 값은 토글, 정수는 스테퍼로 편집. 실수·문자열은 값만 보여준다(읽기 전용).
  - 조절한 값은 `config.ini` **제자리에 저장**된다 — 주석·순서·나머지 줄은 그대로.
    (왕복되는 표준 int32 만 편집 대상, 실제로 바뀐 키만 기록 = 남의 줄 보존)
  - 맨 위에 "값 변경 후 모드 리로드/재시작 필요" 안내 한 줄.
- **모드 제작자가 아무것도 안 해도** 된다. dsplugin.ini 를 둔 모드는 종전처럼
  선언한 옵션만 뜨고(계약 우선), config.ini 브리지는 옵션 선언이 없을 때만 켜진다.

**부트 블랙박스 — 크래시가 "어디서" 났는지 기록·판정 (사용자 제안)**
- 세션 진행 단계(부팅 → 엔진 → 타이틀 → 게임 로딩)를 파일에 즉시 기록하고,
  UE4SS 가 모드를 시작할 때마다 어느 모드까지 시작됐는지 수집한다. 크래시 후
  다음 부팅의 안내 팝업이 이 기록으로 판정한다:
  - 모드 시작 단계에서 죽음 → **마지막으로 시작된 모드를 이름으로 지목**
  - 게임 시작/로딩 중 죽음 → 이름을 못 대므로 이때만 **pak 모드를 지목**
  - 플레이 중 죽음(로딩 후 5분 경과) → 단정하지 않고 참고 정보만
- 죽기 직전의 UE4SS 로그 꼬리를 5초마다 보존(`lastlog_prev.txt`) — UE4SS 로그는
  부팅마다 지워져서, 이것 없이는 사망 직전 기록이 소실됐다.

**입력 진단 기록 (컨트롤러 문제 조사용)**
- 타이틀 화면에서 들어오는 입력(패드·키보드)과 컨트롤러 인식 상태를
  `Mods\DsCppModManager\inputlog\날짜.log` 에 남긴다. "컨트롤러를 인식 못 한다" 같은
  제보를 받았을 때 이 파일 하나로 원인을 가릴 수 있다(패드가 XInput 에 안 잡히는지,
  스팀이 키보드로 바꿔 보내는지, 장치 이름이 무엇인지).
- **기록 범위는 타이틀 화면뿐**이고, 게임 플레이 중에는 기록하지 않는다.
  파일은 컴퓨터 밖으로 나가지 않는다.
- **키보드는 무엇을 눌렀는지 남기지 않는다** — "1초 동안 키 입력 N회" 라는 횟수만
  적는다(컨트롤러가 키보드 신호로 오는지 판별하는 용도). 타이틀에서 스팀
  오버레이를 열어 타자를 치면 그 횟수도 집계되지만, 내용은 남지 않는다.
- 기록을 끄려면 매니저 폴더에 `inputlog_off.txt` 파일을 만들면 된다.
- 파일은 하루 단위(게임을 켠 날짜)로 쌓이고, 14일 지난 것은 자동 정리된다.

**넥서스 버그리포트 대응 (2026-08-16, wsesrdtf 리포트)**
- **"켜져 있는데 적용이 안 되던" 문제 해결** — 켜진 상태로 배포된 모드를 넣으면
  목록에는 켜짐으로 보이지만 게임이 그 모드를 찾지 못해, 패널에서 껐다 켜야만
  적용되던 문제. 이제 매니저가 게임 시작 때와 패널을 열 때 알아서 연결해 두므로
  **게임을 다시 켜기만 하면** 적용된다.
- **"재시작 필요" 표시** — 켜짐으로 보이지만 이번 실행에 아직 로드되지 않은 모드의
  행에 주황색으로 표시된다. 게임을 다시 켜면 적용된다는 뜻.
- **모드 업데이트 후 pak 잔류 해결** — 모드를 새 버전으로 갈아끼우면 이전 판의
  pak 링크가 끄기로도 안 지워지던 문제. 이제 링크를 걸 때 장부(paklinks.txt)에
  기록해 두고, 끄기·부팅 청소가 장부로 잔재를 판별해 걷어낸다. 켜진 모드의
  구판 잔재는 부팅 때 새 판으로 자동 교체(재링크).
- pak 대상 폴더(pak_target)를 바꾼 모드의 옛 폴더 쪽 잔류 링크도 토글 때 자동
  정리 — 이중 마운트·오배치 크래시 예방.

**크래시 안전장치 강화 (2026-08-13 실사고에서 나온 3건)**
- 크래시/게임 업데이트 후 안내 팝업이 **실제로 끈 모드 목록**(표시명, pak 표기)을
  보여준다. 종전에는 "마지막으로 기록을 남긴 모드" 하나만 지목했는데, pak 모드는
  기록을 안 남겨 절대 지목되지 못하고 엉뚱한 모드가 뒤집어쓰는 사고가 있었다
  (실사고: 외형변경 pak 크래시에 음식 모드가 지목됨). 기록 모드는 참고로만 표시.
- **게임 시작 최초 순간(엔진 초기화 전)에 pak 안전 조치** — 직전 크래시나 게임
  업데이트가 감지되면 켜져 있던 pak 링크를 엔진이 열기 전에 미리 해제한다.
  종전에는 엔진이 pak 을 이미 연 뒤라 해제가 조용히 실패했고, "껐다"고 표시된
  pak 이 실제로는 매 부팅 로드되고 있었다. 꺼진 pak 의 잔류 링크도 매 부팅 청소.
- pak 링크 해제 실패를 로그에 남긴다 (조용한 실패 금지).

**수정**
- **타이틀 메뉴에서 "모드매니저" 위치가 흔들리던 문제 수정** (넥서스 리포트 3번) —
  인게임에서 타이틀로 돌아온 뒤 "모드매니저"에 커서를 올리면 나가기와 순서가
  바뀌며 맨 아래로 내려가던 증상. 이제 항상 설정과 나가기 사이에 고정되고,
  메뉴가 다시 만들어져도 자리가 잡힐 때까지 숨겼다가 제자리에 나타난다.
- 영어로 쓸 때 타이틀 메뉴의 "나가기"만 한글로 표시되던 문제 수정.
- 패널에서 패드로 아래로 내릴 때 화면 밖 항목부터 **스크롤이 따라오지 않던** 문제
  수정 — 마우스로 한 번 굴려야 정상 동작하던 증상.
- 모드가 보낸 안내 팝업의 **긴 한글 문구가 중간에 잘리던** 문제 수정.
- 타이틀 메뉴에서 매니저가 게임의 방향키 이동 규칙을 건드리던 부분 제거 — 패드로
  메뉴를 오르내릴 때 걸리던 문제의 원인이 될 수 있었다.
- 패드 입력을 읽는 경로(XInput) 보완 — 게임과 같은 경로로도 컨트롤러를 찾는다.
- 한 모드가 가질 수 있는 옵션 개수 확대(16 → 64) — config.ini 항목이 많은 모드 대응.
- 재시작 안내 팝업의 "확인" 버튼에 패드 (A) 아이콘 추가 — 패드 사용 중에만 표시.
- Y 아이콘(패드로 매니저 여는 표시): 글자가 밀리지 않게 고정(글자 중앙 불변), 확대(46px),
  세로 중앙 정렬, 언어별 간격(한국어/영어 라벨 폭에 맞춤).

## v0.40 — 2026-08-10

**언어**
- 언어 선택(한국어/English) — 매니저 UI 전면 번역, [기본] 탭에 `언어(Language)` 콤보
- 게임 언어 설정(`LanguageText`)을 따라 자동 선택되고, **게임 언어를 바꾸면 매니저도
  2초 안에 따라간다** (콤보로 직접 고른 선택은 게임 언어를 다시 바꾸기 전까지 유지)
- 플러그인용 언어 방송 `dsmmlang.txt` — 지원하는 모드는 매니저와 같은 언어로 문구를
  맞출 수 있다 (`dsmm_options.lua` 의 `mm.lang()`)
- 게임 언어 전환 때 타이틀 메뉴 항목이 공란이 되던 문제 수정 (라벨 키퍼)

**게임패드**
- 타이틀 화면에서 **Y 버튼으로 모드매니저 열기** (패드 사용 중엔 "모드매니저" 옆에
  Y 아이콘 표시). 이 게임의 타이틀 메뉴는 방향 이동이 엔진 네이티브 코드로 4개 항목만
  순회하도록 고정돼 있어 방향키로는 모드매니저에 멈출 수 없다 — 다섯 자료구조와
  네이티브 함수까지 조사해 확인한 뒤 전용 Y 버튼을 진입 경로로 확정했다.
- 패널 전체 패드 조작: 방향키/왼스틱 = 행 이동(크림색 선택 테두리, 게임 설정창과 동일),
  좌/우 = 값 조절(토글·스테퍼·콤보·슬라이더), A = 실행/열기, B = 닫기(ESC 와 동일)
- LB/RB = 모드 ↔ 순서 탭 전환 (탭 옆에 LB/RB 칩 표시)
- 순서 탭: A 로 집고 위/아래로 옮긴 뒤 A 로 놓으면 저장
- 하단에 (A) 선택 · (B) 닫기 힌트 (패드 연결 시)

**표시**
- 모드선택·순서 탭의 각 행에 **모드 종류(Lua / C++ / pak)** 표시
- 옵션 갱신·언어 전환 때 패널이 1초쯤 사라지던 공백 제거
  (새 패널을 먼저 그린 뒤 옛것을 걷는 방식으로 교체)

**게임패드 2차 (라이브 피드백)**
- 패널이 열린 동안 게임이 패드를 함께 처리하던 문제 차단 — 모드 조작 중 게임이
  조용히 종료되던 사고("나가기" 오발)와 B 가 설정창을 열던 문제의 뿌리
- 선택 표시를 행 전체 칠하기 → **외곽선만**으로 (게임 설정창과 동형)
- LB/RB·A/B 를 게임 스타일 **아이콘**으로, 패드를 쓸 때만 표시(키/마 입력 시 즉시 숨김)
- 하단의 "ESC 또는 X 로 닫기 · 버전" 문구 제거
- 드롭다운 패드 내비: A 열기 → 위/아래 항목 이동 → A 선택, B 는 드롭다운만 닫음
- 게임 설정에서 언어를 바꾼 직후 매니저에 바로 들어와도 언어가 맞도록

**동작 수정**
- 게임 창이 앞에 없을 때는 입력을 받지 않음 — 게임 위에 겹친 다른 창(탐색기 등)을
  클릭하면 그 자리의 게임 컨트롤이 눌리던 문제, 다른 창에 타자 치면 키 바인딩에
  잡히던 문제 수정
- 모드가 보낸 안내 팝업에 **발신자(모드 이름) 표시** — 매니저/게임의 말처럼 읽히던
  혼동 제거
- bootstate 에 매니저 버전 기록 — 매니저 업데이트를 게임 패치와 구분해 로그에 남김
- 배경에서 마우스를 뗐을 때 드래그/스크롤 상태가 썩던 문제, 게임 설정 저장 순간
  언어가 한 틱 튀던 문제, 라벨 키퍼의 FText 누수 수정 (리뷰에서 확정된 3건)
